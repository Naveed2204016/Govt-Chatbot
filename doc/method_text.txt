Proposed Methodology

We investigated four approaches to Bangla government-service question answering: prompting without parameter updates, supervised fine-tuning, retrieval-augmented generation (RAG), and RAG combined with fine-tuning. The prompting experiments included zero-shot and few-shot settings, with explicit chain-of-thought (CoT) prompting implemented for Llama, Qwen, and Mistral. These approaches examine the contribution of task demonstrations, domain adaptation, and external information to answer generation. The experiments cover passport services, National Identity (NID) services, birth and death registration, and Taxpayer Identification Number (TIN) services.

System Overview

The framework uses the QA dataset and knowledge base for different purposes. Training QA pairs provide demonstrations for selected few-shot experiments and supervision for model adaptation. The knowledge base supplies passages for retrieval-based inference. The dataset contains 938 training pairs and 248 test pairs. Each test instance provides a question and a reference answer; the retrieval pipeline additionally uses its service-domain label. Reference answers are used for evaluation rather than included in the test-time generation prompt.

For prompting and fine-tuning without retrieval, the generator answers from its pretrained or adapted parameters and the supplied instructions. For RAG, a hybrid retriever combines dense and sparse search, a reranker selects relevant passages, and the pretrained generator produces an answer from this context. RAG with fine-tuning follows the same retrieval process and replaces the pretrained generator with a generator carrying domain-trained LoRA adapters. Figure 1 shows the overall workflow.

Language Models and Prompting Baselines

The main model families were Llama-3.1-8B-Instruct, Qwen2.5-7B-Instruct, and Mistral-7B-Instruct-v0.3. These models were evaluated using prompting, supervised fine-tuning, RAG, and RAG combined with fine-tuning. We also examined BanglaLLM/bangla-llama-7b-instruct-v0.1 in zero-shot and few-shot settings.

Zero-Shot Prompting

In the zero-shot setting, each model receives a service question and an instruction to provide a concise answer in Bangla. No demonstrations or retrieved passages are included. The prompts emphasize relevant service information, including fees, required documents, and procedures. Llama, Qwen, and Mistral use their model-specific chat templates. BanglaLLM uses its instruction format with Instruction and Response delimiters.

Few-Shot Prompting

Few-shot prompts prepend fixed question–answer demonstrations to the test question. Llama uses three examples sampled from the training portion of the corresponding service domain with random seed 42. Qwen uses three fixed examples selected from a shuffled training pool with seed 42. Its selection code removes normalized exact question overlap with the test set, removes duplicate questions, and limits each demonstration pair to 512 model tokens. BanglaLLM also uses three training demonstrations with overlap filtering and a demonstration-length constraint. These demonstrations remain fixed across test questions, whereas Llama selects a separate fixed set for each domain.

Mistral uses five manually specified demonstrations shared across all questions. They illustrate concise answers to service queries and how to respond when a fee or processing time is uncertain.

Few-Shot Prompting with Chain-of-Thought

The few-shot CoT setting combines QA demonstrations with an instruction to analyze the question briefly before producing a final answer. Llama and Qwen use three demonstrations, while Mistral uses five. Llama follows the same general analysis-then-answer prompting approach. Qwen's demonstration answers are wrapped with a final-answer marker, while Mistral's worked examples include both reasoning and an answer. The final answer is used for reference-based evaluation.

Supervised Fine-Tuning

Training Representation

The Llama, Qwen, and Mistral training pipelines combine the four service-domain training sets. Each example is formatted as a conversation containing an instruction, the user question, and the reference answer. A nonempty input field is appended to the question. The model-specific chat template converts the conversation into a training sequence. Training uses the serialized conversation text with the supervised fine-tuning trainer.

Parameter-Efficient Adaptation

Llama, Qwen, and Mistral are adapted using QLoRA-style training through Unsloth: the backbone is loaded in 4-bit form and low-rank adapters are trained. The adapters have rank 16, scaling parameter alpha 16, zero dropout, and no trainable bias. They are inserted into the attention projections q_proj, k_proj, v_proj, and o_proj, together with the feed-forward projections gate_proj, up_proj, and down_proj. Unsloth gradient checkpointing reduces activation-memory requirements.

For an adapted linear layer, the effective weight equals the frozen 4-bit backbone weight plus the product of two trainable low-rank matrices. The adapter contribution is scaled by alpha divided by the rank, giving a scaling factor of 1.

Optimization

The Llama, Qwen, and Mistral training configurations use three epochs, a learning rate of 0.0002, and the 8-bit AdamW optimizer. The per-device batch size is two with four gradient-accumulation steps, giving an effective batch size of eight sequences for a single GPU. Training uses a cosine learning-rate schedule, a warmup ratio of 0.03, weight decay of 0.01, a maximum sequence length of 1,024 tokens, and sequence packing. The random seed is 3407. Checkpoints are saved after each epoch, and the trained adapters and tokenizers are retained for subsequent inference. The final adapted generators are evaluated directly for standalone fine-tuning and combined with retrieved context for RAG with fine-tuning.

Retrieval-Augmented Generation

Knowledge-Base Preparation

The retrieval pipeline divides each nonempty knowledge-base record into passages of at most 180 whitespace-delimited words with an overlap of 30 words. Each passage retains its document identifier, service domain, title, topic, and source URL. The indexed text concatenates the title, topic, and passage content. The knowledge-base version used in the experiments produces 1,284 passages across the four service domains.

Dense and Sparse Retrieval

Dense representations are generated with BAAI/bge-m3. Passage embeddings are computed in batches of eight, normalized to unit length, and stored as float32 vectors in a FAISS IndexFlatIP index. Query embeddings are normalized in the same way. Inner-product ranking therefore corresponds to cosine-similarity ranking.

Sparse retrieval uses BM25Okapi. Before tokenization, text is normalized with Unicode NFKC, Bangla digits are converted to Latin digits, and Latin characters are lowercased. A regular expression extracts Bangla character sequences, English words, and numerical tokens. BM25 uses the library's default parameters.

For each question, both rankings are filtered to its supplied service-domain label. Up to 100 passages per retrieval method are retained after filtering. This domain-conditioned search restricts retrieval to information associated with the relevant government service.

Rank Fusion and Reranking

Dense and sparse rankings are combined using reciprocal rank fusion (RRF). For each retrieval list containing a passage, its contribution is one divided by the sum of 60 and the passage's rank. These contributions are added to obtain the fused score. Ranks start at one, and a passage contributes zero for a list in which it does not appear. Both retrievers have equal weight. The 25 highest-scoring passages form the reranking candidate set.

The model BAAI/bge-reranker-v2-m3 scores each question–passage pair. Reranking uses batches of four and a maximum pair length of 512 model tokens. Candidates are sorted by the model's raw relevance logits, and the top five passages are selected for generation. The retrieval settings are summarized below.

Context-Grounded Generation

The generator receives the question and numbered context blocks containing the selected passage titles and text. Its instruction requests a concise Bangla answer based on the supplied information, with attention to fees, numbers, processing times, and required documents. If the context does not contain the answer, the prompt asks the model to state that the information is unavailable.

Retrieval results are saved and reused across the Llama, Qwen, and Mistral RAG and combined RAG with fine-tuning experiments. The stored retrieval metadata include document identifiers, source URLs, and retrieval scores, supporting inspection of the passages selected for each question.

Combining Retrieval with Fine-Tuning

The combined approach supplies the same retrieved passages to a generator equipped with domain-trained adapters. Each model is first adapted using the training QA pairs. At inference time, its adapters are applied to the corresponding backbone, and the question is presented together with the top five reranked passages. The retriever and reranker remain fixed during generator adaptation.

This design allows external facts to be supplied through the knowledge base while adapter training influences domain terminology and response behavior. Reusing stored retrievals also keeps passage selection fixed across the generator variants that consume the same cache. Updating the external knowledge base would require rebuilding the affected retrieval artifacts, without necessarily retraining the adapters.

Inference and Evaluation Protocol

The standard Hugging Face inference loaders use 4-bit NF4 quantization with double quantization and FP16 computation. The Unsloth-based fine-tuned generators use their corresponding 4-bit loading paths. Llama and Mistral prompting experiments use greedy generation with a 500-token output cap and repetition penalty 1.05. Qwen's prompting experiments use greedy generation with adaptive output budgets: 512, 1,024, 2,048, and 4,096 tokens for zero-shot, and 512 followed by 1,024 for few-shot variants. BanglaLLM instead uses seeded sampling with temperature 0.6, top-p 0.9, top-k 50, and a 256-token output cap.

RAG and RAG with fine-tuning use greedy decoding, repetition penalty 1.05, and input truncation at 7,000 tokens. Qwen RAG allows 450 new tokens; the other RAG and combined configurations allow 500. Llama's standalone fine-tuning evaluation also allows 500 new tokens.

Generated answers are compared with the reference answers using normalized Exact Match, fuzzy matching, BLEU, ROUGE-1, ROUGE-2, ROUGE-L, Token F1, and multilingual BERTScore. In the common RAG evaluation implementation, normalization applies Unicode NFKC, digit conversion, lowercasing, punctuation filtering, and whitespace normalization. Token F1 uses multiset token overlap; fuzzy matching uses RapidFuzz's token-set ratio. ROUGE-N measures token n-gram overlap, while ROUGE-L uses the longest common subsequence. Corpus BLEU uses SacreBLEU with pretokenized text, exponential smoothing, and effective order. BERTScore uses bert-base-multilingual-cased with IDF weighting and baseline rescaling disabled. Some baseline and Qwen fine-tuning evaluations additionally report METEOR and token-level precision and recall.

The held-out evaluation set contains 248 questions spanning the four government-service domains. Predictions are stored with their corresponding questions and reference answers for metric computation. For retrieval-based comparisons, the same stored passages are supplied to the pretrained and fine-tuned generators.
